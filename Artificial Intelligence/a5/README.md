## 1. Problem Overview

This lab addresses a variant of the **Travelling Salesperson Problem (TSP)**. A delivery agent starts from a central warehouse (W), visits each delivery location (A through G) exactly once, and returns to the warehouse. The goal is to find the route permutation that minimizes total round-trip travelling distance — an NP-hard combinatorial optimization problem for which local search heuristics such as Hill Climbing and Simulated Annealing provide efficient, if not always globally optimal, solutions.

### 1.1 Location Coordinates

| Location | Coordinates (x, y) |
| :--- | :---: |
| Warehouse W | (0, 0) |
| A | (2, 6) |
| B | (5, 2) |
| C | (6, 7) |
| D | (8, 3) |
| E | (1, 4) |
| F | (7, 6) |
| G | (3, 1) |

### 1.2 Distance Formula (Euclidean Distance)

The distance between any two locations *i* and *j*:

$$d(i, j) = \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2}$$

### 1.3 Solution Representation

A candidate solution is a permutation of the 7 delivery locations. For example, `[A, B, C, D, E, F, G]` represents the tour:

$$W \to A \to B \to C \to D \to E \to F \to G \to W$$

Total travel cost:

$$\text{Cost} = d(W, \text{route}[0]) + \sum_{k=0}^{n-2} d(\text{route}[k], \text{route}[k+1]) + d(\text{route}[n-1], W)$$

### 1.4 Search Space Size

With 7 locations and a fixed start/end at W, the number of distinct tours is:

$$\frac{7!}{2} = 2520 \text{ unique routes (accounting for direction symmetry)}$$

This is small enough to brute-force here, but the same local search methods scale to problem sizes where exhaustive search is intractable — which is the practical motivation for using them.

### 1.5 Neighbourhood Generation

Neighbours are generated by swapping any two delivery locations in the current permutation. For n = 7:

$$\binom{n}{2} = \frac{7 \times 6}{2} = 21 \text{ possible swap neighbours}$$

## 3. Question 1: Delivery Route Optimization using Hill Climbing

### 3.1 Procedure (Steepest-Descent Hill Climbing)

```text
1. Generate a random initial route and compute its cost.
2. Generate all 21 neighbours by pairwise-swapping two locations.
3. Compute the cost of each neighbour.
4. Select the neighbour with minimum cost.
5. If that neighbour is strictly better than the current route, move to it.
6. Repeat until no neighbour improves on the current route (local optimum).
```

Hill Climbing is a **greedy, memoryless** search: it only ever looks one move ahead and always takes the best available move, with no mechanism to escape a local optimum once reached.

## 4. Question 2: Delivery Route Optimization using Simulated Annealing

### 4.1 Initial Parameter Values

| Parameter | Value |
| :--- | :---: |
| Initial Temperature (T) | 100 |
| Cooling Rate (alpha) | 0.95 |
| Minimum Temperature (termination) | 0.1 |
| Temperature Update Rule | T = alpha × T |

### 4.2 Procedure

```text
1.  Generate a random initial route and compute its cost.
2.  Set T = 100.
3.  Randomly swap two locations to get a neighbouring route.
4.  Compute Delta E = Cost(new) - Cost(current).
5.  If Delta E < 0, accept the move unconditionally.
6.  Else compute P = exp(-Delta E / T).
7.  Draw r ~ Uniform(0, 1); accept the move if r < P.
8.  Cool the temperature: T = alpha * T.
9.  Repeat until T < 0.1.
10. Track and report the best route seen across the whole run.
```

### 4.3 Expected Number of Iterations

$$100 \times (0.95)^k < 0.1 \implies 0.95^k < 0.001 \implies k = \left\lceil \frac{\ln(0.001)}{\ln(0.95)} \right\rceil = 135 \text{ iterations}$$

### 4.4 Why the Boltzmann Criterion Works

At high temperature, `P = exp(-ΔE/T) ≈ 1` for most `ΔE`, so nearly all moves — including worsening ones — are accepted, letting the search explore broadly and jump out of local optima. As `T → 0`, `P → 0` for any positive `ΔE`, so the algorithm behaves increasingly like pure Hill Climbing, refining around whatever basin it currently occupies. This annealing schedule is what allows SA to trade exploration for exploitation over time, rather than committing to one or the other.

## 6. Complexity Analysis

| Aspect | Hill Climbing | Simulated Annealing |
| :--- | :--- | :--- |
| Cost evaluations per iteration | O(n²) — all 21 neighbours | O(1) — one random neighbour |
| Total iterations | Small, run-dependent (2–6 here) | Fixed by cooling schedule (135 here) |
| Total cost evaluations (worst case) | O(iterations × n²) | O(iterations) |
| Memory | Current route + best neighbour | Current route + best-so-far route |
| Guarantees | Terminates at a local optimum | No formal termination guarantee on optimality; converges probabilistically as T → 0 |

Despite doing far fewer iterations, Hill Climbing spends more total work per iteration since it evaluates the full neighbourhood; Simulated Annealing does cheaper, more numerous iterations but relies on randomness and the cooling schedule to find good solutions.

## 7. Analytical Insights and Discussion

1. **Solution quality and escaping local optima** — Hill Climbing makes strictly greedy moves. If the initial route falls in a basin leading to a local minimum, it terminates there (e.g., stopping at 26.2509 or 28.1512) without further exploration. Simulated Annealing's controlled stochasticity — accepting uphill moves with probability `exp(-ΔE/T)` — lets it escape such basins, particularly while T is still high.

2. **Computational overhead vs. exploration** — Hill Climbing exhaustively evaluates all 21 neighbours at every step but needs only 2–6 iterations to converge. Simulated Annealing evaluates just one random neighbour per step but runs for a fixed 135 iterations regardless of how quickly it finds a good solution, trading per-step cost for broader exploration.

3. **Sensitivity to initialization** — Hill Climbing's final cost varies significantly with the starting route, since it can only move downhill from wherever it starts. Simulated Annealing is comparatively robust to initialization, since early high-temperature exploration lets it wander away from a poor starting basin.

4. **Practical takeaway** — For small, cheaply-evaluated neighbourhoods, Hill Climbing's exhaustive-neighbour approach converges fast but risks poor local optima. Simulated Annealing costs more iterations but is the more reliable choice when solution quality matters more than raw iteration count, or when the landscape is known to have many local optima.

## 8. Conclusion

Across 5 trials, Simulated Annealing matched Hill Climbing's best-case cost (23.6194) but did not consistently outperform it, since HC also reached the global optimum in 2 of 5 runs. The results illustrate a common trade-off in local search: Hill Climbing is fast and cheap per run but inconsistent, while Simulated Annealing is more computationally expensive but less sensitive to where the search starts. For this small 7-node problem the difference in solution quality is modest, but the gap would be expected to widen in favor of Simulated Annealing (or other exploration-based methods) as the number of locations — and therefore the number of local optima — grows.
